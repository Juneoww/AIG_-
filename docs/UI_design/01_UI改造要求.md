# 前端 UI 改造要求

日期：2026-10-14  
工作分支：`feat/frontend-ui-redesign`  
状态：需求初版；布局方向已由用户明确，具体页面尚未实现。

## 1. 目标与依据

借鉴 [AIG_UI_Design](https://github.com/Juneoww/AIG_UI_Design) 的布局、视觉层级与交互框架，将现有平台改为以检测功能为中心的工作台。

**功能、参数、任务协议和结果内容以当前 AI-Infra-Guard 为准。** 原型的入口数量、演示规则、模拟扫描、大模型模拟研判和预设结果不作为实现依据。

用户已明确的主结构：左侧放任务功能入口；点击入口后，右侧显示对应功能页；功能页上方发起评测，下方展示该类历史任务。

新增前置要求：**先检查并完成现有平台前后端解耦，再改 UI。** 当前独立开发已具备，但构建、部署、发布和任务创建依赖仍未达标。详见 [解耦评估与方案](../System_Split/01_前后端解耦评估与方案.md) 和 [解耦实施计划](../System_Split/02_前后端解耦实施计划.md)。

## 3. 功能范围

### 3.1 当前可发起的任务入口

依据 `frontend/src/config/mcpServices.ts`，当前选择器配置了以下五类服务。建议迁移为左侧独立入口，名称和帮助文案继续使用现有中英翻译。

| 功能入口 | 真实任务类型 | 上方发起区域应保留的能力 |
| --- | --- | --- |
| AI 基础设施扫描 | `AI-Infra-Scan` | 目标输入、现有附件能力、模型配置、HTTP Header、端口发现模式 |
| MCP 扫描 | `Mcp-Scan` | 服务或仓库地址、代码包上传、模型配置、插件选择、HTTP Header |
| Skill 扫描 | `Skill-Scan` | 仓库地址、代码包上传、模型配置、插件选择 |
| Agent 扫描 | `Agent-Scan` | 已配置 Agent 选择及现有模型配置，保留对应字段语义 |
| 大模型安全体检 | `Model-Redteam-Report` | 单/多目标模型、现有评测集、评测文件、评测数量、攻击方法及评分模型配置 |

表格描述已有能力，不表示所有字段都必须显示或必填。显示条件、默认值和校验以现有配置、环境开关及真实请求契约为准。

### 3.2 六种类型的兼容要求

`frontend/src/types/index.ts` 另定义了 `Model-Jailbreak`，对应“大模型一键越狱”。当前服务选择器没有配置这个发起入口，但仍有任务类型、历史结果和报告展示代码。

- 保留其历史任务、详情及 `/report/:sessionId` 报告兼容能力。
- 不因改 UI 而删除该类型，也不默认新增发起入口。
- 通用历史任务入口须能访问六种类型；不能仅以五个当前发起入口限制历史任务可见范围。
- 不引入原型专属的 `Claw-Scan`，不把 MCP 与 Skill 合并，也不把安全体检与一键越狱改成同一种任务。

### 3.3 其他已有能力

模型管理、Agent 配置、知识库/规则/评测集管理、帮助文档、语言切换、版本提示及 `/poison-detect` 模型代理检测等已有能力保持可达。新导航可将管理和帮助放在辅助区域，具体位置随视觉设计细化。

不为填满原型页面增加新的统计指标、批量操作或导出格式。已有打印、导出、下载能力按当前各引擎实际支持情况保留。

## 4. 页面要求

### R00：平台解耦前置门槛

- 前后端独立构建、运行、部署、更新和回退；后端 API-only 产物不依赖 frontend、Node、dist 或产品静态资源。
- 前端通过独立静态服务/网关连接 API；同源 `/api` 可以保留，不要求拆 Git 仓库或强制直接跨域。
- 后端创建和执行任务不依赖浏览器 SSE；SSE 是可选观察通道，离线期间事件和结果仍保存。
- 第一阶段保持现有 UI，先迁移公共网络/状态边界、创建生命周期、晚订阅恢复、构建和发布方式。
- 新分离部署成为后续默认交付；原一体化方式仅作明确标识的兼容渠道。
- 解耦评估中的 D01–D09 有验证证据后，才进入下列工作台 UI 改造。

### R01：左侧功能导航

- 导航展示检测功能，而非将历史任务作为主要导航。
- 当前入口明确高亮，图标、名称和分组保持一致。
- 点击后更新右侧内容，浏览器前进、后退及页面刷新能恢复有效入口。
- 辅助区域提供全类型历史任务和已有管理、帮助等功能的入口。

### R02：右侧功能页

```text
┌────────────────┬──────────────────────────────────────┐
│ 检测功能入口   │ 当前功能名称 / 简要说明               │
│                ├──────────────────────────────────────┤
│ 基础设施扫描   │ 发起评测                              │
│ MCP 扫描       │ 目标 / 模型 / 附件 / 参数 / 开始按钮   │
│ Skill 扫描     ├──────────────────────────────────────┤
│ Agent 扫描     │ 本功能历史任务                        │
│ 安全体检       │ 搜索 / 状态筛选 / 列表 / 任务操作      │
│                │                                      │
│ 历史 / 管理等  │ 选中任务 → 执行详情 / 结果 / 报告      │
└────────────────┴──────────────────────────────────────┘
```

- 上下区域构成同一个功能工作台，避免用户必须进入聊天页面才能创建任务。
- 复用一致的间距、表单、按钮、状态标签和列表样式；各功能保留自己的输入字段。
- 初期建议默认打开基础设施扫描页；已有有效入口地址优先于默认值。

### R03：发起评测

- 保留当前输入、附件类型限制、模型选择规则、默认值与条件显示逻辑。
- 基础设施扫描默认 `full_tcp`，可选择 `fixed_ai`；不因布局变化改变扫描语义。
- 可选参数集中到清晰的配置区域，避免一次显示过多字段。
- 提交中禁止重复点击；失败显示真实原因并保留可重试输入。
- 上传未完成或失败时不能将任务显示为已成功发起。
- 解耦后的 POST 不等待 SSE，返回现有分发结果；成功后通过订阅与历史快照对账恢复执行信息，任务在订阅前完成也能看到结果。
- POST 在途可显示“提交中”占位；只有返回业务成功才确认已接受。过渡期间连接旧后端时仍需并行建 SSE，不能把新顺序提前用于未解耦后端。
- 明确的 POST 业务失败清理临时订阅/占位；网络失败导致结果未知时先查询同 sessionId，再决定恢复或重试，避免重复扫描。确认响应不得覆盖已到达终态。
- 表单中不同用途的模型字段按现有规则写入对应参数，不能因统一表单交换目标模型与评估模型。

### R04：历史任务

- 各功能页默认只展示本任务类型；辅助历史入口可以查看全部类型，包括 `Model-Jailbreak`。
- 展示任务名称/标识、创建时间、真实状态和已有操作；其他摘要仅在有可靠来源时展示。
- 支持现有服务器搜索、手动刷新和必要的状态筛选；状态筛选可在当前已加载数据上完成。
- 空列表、加载中、查询失败、没有匹配结果分别显示。
- 长列表初期采用前端分页；必须标注其针对已加载集合，不能宣称后端已有分页能力。
- 搜索响应晚到时不能覆盖用户切换后的功能页。
- 终止仅对支持终止的执行中任务开放；删除、重命名及已有分享操作沿用真实接口和既有确认方式。
- 当前选中任务被删除后清理选择与详情，避免显示另一任务的旧结果。
- 页面刷新从后端恢复历史，禁止以演示数据或浏览器内存代替后端记录。

### R05：任务详情、结果与报告

- 建议在历史列表选中任务后打开详情抽屉，桌面端侧向展开，窄屏可全屏展示；这一细节是初版建议，不是用户已确认的最终视觉稿。
- 提供执行信息与结果两个清晰区域，保留步骤、工具调用、日志、错误明细及引擎专属报告。
- 关闭详情后保留功能页表单和列表筛选状态。
- 如现有任务支持追加消息或继续交互，在详情中保留该能力，不因移除主聊天布局丢失它。
- 复用各类 `detailPanel`，不强行压成原型的统一漏洞列表。
- 保留 `/report/:sessionId`、`/help` 和 `/poison-detect` 等已有地址；新增路由不得使旧报告链接失效。

### R06：实时执行与异常

- 执行状态来自后端任务状态和 SSE；没有真实百分比时展示阶段和状态，不生成假进度。
- SSE 业务错误与网络断线区分处理；保留重连、迟到错误补充、终态清理和状态轮询补偿。
- 切换功能页不会终止后端任务；订阅生命周期与任务关联，而非与表单显示关联。
- 同一任务不创建相互冲突的重复订阅；终止、删除或应用卸载时清理对应资源。
- 历史重载和实时事件应产生一致的详情；错误明细不能被较简略的后续事件覆盖。

### R07：视觉、可访问性和兼容

- 借鉴原型的浅色背景、左侧导航、卡片与表格层级；字体、强调色和细节在后续视觉稿中确定。
- 沿用现有 React 18、Vite 6、Tailwind CSS 3、Radix/shadcn 组件和中英双语体系。
- 不为复刻原型升级 React、Vite 或 Tailwind 大版本。
- 桌面端优先；窄屏下导航可收起，表单与详情不溢出，表格可横向滚动。
- 标签与表单控件对应，导航和抽屉可用键盘操作，状态不能只靠颜色区分。
- 不新增运行时外部字体、远程图片或云模型依赖，以适应既有内网部署。
- 日志、展示和导出沿用现有凭据保护要求，不暴露配置密钥。
- 保留必要的项目品牌和 Tencent Zhuque Lab 归属说明，遵循仓库 NOTICE。

## 5. 本期技术边界

- 保持 Go/Python 扫描算法、规则、任务类型、数据库记录及模型语义；允许为解耦调整任务创建/观察生命周期和静态路由。
- 第一阶段解除 Go 产品静态内嵌构建依赖，提供独立前端与 API-only 后端；新生产方式采用分离产物。
- 创建成功不依赖 SSE；请求/响应形状优先兼容，行为变化须更新中英 API 说明、Swagger 及必要生成代码。
- 更新分离 Compose、健康检查、构建发布和离线打包/迁移说明；本轮不覆盖旧发布包、运行升级脚本或自动发布。
- 允许在前端抽取 API、上传、状态转换和 SSE 逻辑，以支持新页面。
- 原有私有 overlay 的 `AppShell`、`AuthGate` 和扩展路由契约继续保留。
- 如发现必须修改接口，先形成明确差异与影响记录，并按 AGENTS.md 同步检查 API 文档。
