# 前端 UI 改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking. 如采用并行实施，使用 `subagent-driven-development`，并按文件责任划分工作。

**Goal:** 先完成现有平台前后端解耦，再保留现有检测能力，将 UI 迁移为左侧功能入口、右侧上方发起评测、下方历史任务的工作台。

**Architecture:** 第一阶段解除任务执行对 SSE 的门槛，形成 API-only 后端与独立前端产物，并让现有 UI 使用可恢复的观察链路。第二阶段复用 API、AppProvider、模型/规则管理及引擎结果组件，构建工作台；生产使用分离默认部署。

**Tech Stack:** React 18、TypeScript、Vite 6、Tailwind CSS 3、Radix/shadcn、react-router v6、react-i18next；后端沿用现有 Go/Python。

日期：2026-10-14；分支：`feat/frontend-ui-redesign`。  
依据：[UI 改造要求](01_UI改造要求.md)、[UI 改造说明](03_UI改造说明.md)、[解耦评估与方案](../System_Split/01_前后端解耦评估与方案.md)。  
状态：新增解耦前置阶段的修订版已通过独立审阅，实施任务均未执行。

## 4. 依赖与阶段交付

`平台解耦 D1–D7 → D01–D09 验收 → UI Task 1–5 补充核验 → Task 6 → Task 7 → Task 8 → Task 9 → Task 10`。

Task 2/3/4 的接口有共同消费者，默认顺序实施以减少共享文件冲突。功能表单在公共提交、历史和订阅链路稳定后才能分工实现。

- 第一阶段：平台解耦、独立构建/发布和无浏览器执行通过验收，旧 UI 保持可用。
- 第二阶段：工作台导航、历史及基础设施扫描先完成真实闭环。
- 第三阶段：MCP、Skill、Agent、安全体检迁移完成。
- 第四阶段：辅助功能、视觉细节、联调和独立生产产物验收完成。

每个阶段结束时先检查 diff 与测试，再形成独立提交；提交只纳入本轮解耦与 UI 改造相关文件，不夹带工作区原有无关离线升级改动。远端推送和发布不属于本次文档任务。
