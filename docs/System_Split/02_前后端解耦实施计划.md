# 前后端解耦实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. 如分工实现，需先明确共享任务状态、网关和构建文件的唯一责任方。

**Goal:** 在保持现有 UI 和检测能力的前提下，使前端、API 后端独立构建/部署/更新，且后端任务执行不依赖浏览器 SSE。

**Architecture:** 移除 AddTask 的观察连接门槛，保留现有持久化、模型增强、dispatchTask 和响应格式；旧 UI 通过 SSE 与历史快照对账观察任务。提供 API-only 条件编译和独立前端静态服务/网关，新分离部署作为默认交付，原一体化方式仅为兼容渠道。

**Tech Stack:** 现有 React/TypeScript/Vite、Go/Gin、SQLite/GORM、Agent/Python、Docker Compose；前端静态网关选用 Nginx，实施时锁定镜像版本。

日期：2026-10-14；执行分支：`feat/frontend-backend-decoupling`（2026-10-15 从 `c2c1854` 新建）。  
依据：[解耦评估与方案](01_前后端解耦评估与方案.md)、[改造要求](../UI_design/01_UI改造要求.md)。

### D3：解除后端任务创建对 SSE 的依赖

- [ ] 先写失败测试：不创建 SSE，仅调用任务 POST，使用可控 Agent 应在正常分发耗时内返回业务成功，而非等待 100 秒。
- [ ] AddTask 移除等待 HasConnection 的循环；保留预存、内存登记、原 dispatchTask、模型增强和错误清理。
- [ ] 不直接替换成 AddTaskApi，不引入新队列或改变成功响应格式；正常成功继续表示分发完成。
- [ ] 测试无 Agent、无效模型与分发失败仍返回原业务失败，临时数据/资源按既有语义清理。
- [ ] 测试没有 SSE 时 Agent 事件保存、error/done/terminated 状态及结果查询均成立；断线不取消扫描。
- [ ] 测试快速返回结果可能先于创建 POST 返回，创建确认不得把终态回退到 running。
- [ ] 在 `sse_decoupling_test.go` 先增加可控阻塞 Writer 测试，验证慢订阅不会阻止 error/done/terminated 状态保存与后续事件处理；先观察失败，再设置有界推送和必要的通知隔离。持久化失败的行为另行保留并记录，不把通知隔离当成持久化成功。
- [ ] 先增加“连接 A 被 B 替换后 A 才清理”、重复关闭、心跳与事件同时发送测试，再实现按连接身份清理和串行写入；HTTP handler 同时响应请求取消与连接主动关闭，避免只关心跳但请求仍挂起。
- [ ] 详情接口提供可区分的不存在、无权限、服务故障响应，兼容现有响应 envelope；前端适配同步纳入 D4。
- [ ] 更新接口说明并运行聚焦 Go 测试；保存已验证的新创建契约，再调整前端默认订阅顺序。

### D4：适配晚订阅、重连及历史快照

- [ ] 新后端上采用 POST 确认后订阅与快照对账；订阅不再是创建前置，过渡兼容并行建连仍不能重复注册连接。
- [ ] 每次建立/重建观察连接时读取历史详情，订阅建立至快照应用期间协调实时队列，按持久化事件 ID 去重合并。
- [ ] 快照重载不能清空较新的事件、详细错误或终态；终态任务直接显示历史，不开启无限重连。
- [ ] 覆盖任务在订阅前完成、快照读取时新增事件、终态后迟到错误详情、断线再进入等场景。
- [ ] POST 网络错误或取消导致返回未知时，按 D1 契约查询同一 sessionId。预存记录及 assigned_agent 字段只用于对账，不确认分发；成功 POST 或真实执行事件/结果才确认相应执行状态。查询失败、无权限与不存在分开处理，原请求仍可能在途时不自动重发；不能直接生成新 ID 再发起。
- [ ] 覆盖原 POST 延迟落库、预存后分发失败并删除、服务已分发但响应丢失、查询接口故障与用户重复点击；未判定时保留“提交结果待确认”和可继续查询的入口，不宣称 exactly-once。安全重试条件在 D1 固定并记录。
- [ ] 覆盖多标签页观察同一任务：旧连接清理不得影响新连接；被替换页面遵循 D1 策略退回快照/轮询或停止自动抢占，新活动连接继续接收。
- [ ] 删除/终止与应用卸载清理浏览器资源，但不能仅因浏览器离线删除或取消后端任务。
- [ ] 旧报告页、追加交互、历史轮询和各引擎显示通过浏览器验收。

```text
go test ./common/websocket -run 'TestTaskDecoupling' -count=1
go test -race ./common/websocket -run 'TestSSEDecoupling' -count=1
go test -tags api_only ./common/websocket -run 'TestAPIOnly' -count=1

docker compose -f docker-compose.separated.yml config
docker compose -f docker-compose.separated.images.yml config
```

新增测试统一使用 `TestTaskDecoupling...`、`TestSSEDecoupling...`、`TestAPIOnly...` 前缀。如包内旧测试编译失败，先记录完整报错，再采用经说明的聚焦测试组织；不能因 `-run` 过滤就假设所有旧文件不参与编译。`-race` 需要可用的 Go/CGO 工具环境；若本机不支持，在已核验环境运行并记录，不能直接省略后宣称竞态验证通过。输出目录需在实施时指定真实绝对路径，且不覆盖现有可执行文件。

最关键联调证据：不建立 EventSource 的 HTTP 客户端创建任务后，Agent 执行并能查询结果；任务中途关闭 frontend 服务仍继续；前端恢复后日志/错误/结果完整；UI 单独换版，backend/agent 的镜像摘要和数据不变。

本阶段变更任务生命周期、服务构建与发布边界，需运行相关 Go/前端测试和部署验证。规则 YAML/Python 算法不改时不要求机械重复无关检查；如实际触及它们，遵循 AGENTS.md。
