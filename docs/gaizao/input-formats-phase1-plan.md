## 一、背景与目标

《格式清单》描述了改造后产品应支持的扫描目标输入能力:普通扫描支持 URL、域名、IPv4、指定端口、**完整 IPv4 地址范围、CIDR 网段、末尾通配符**,多行混合输入、展开去重、容量上限,以及 `fixed_ai` / `full_tcp` 两种端口发现模式。

本仓库当前(2026-09-20 核对)的目标解析仅覆盖:URL、域名、`IP:端口`、CIDR、多行清单。**地址范围与通配符完全不支持,且以静默失败的方式表现**(区间字符串被当作主机名拼出 `http://a.b.c.d-x.x.x.x` 必然失败,无任何提示)。此外裸 IP 走 nmap 全端口 `1-65535` 硬编码(`common/agent/tasks.go:295`),没有固定 AI 端口的快速模式。

**第一期目标**:后端目标解析层对齐《格式清单》的"支持格式表 / 不支持格式表",不支持写法显式报错;端口模式双模落地(`full_tcp` 默认 + `fixed_ai` 可选);CLI 与前端适配。附件导入、凭据绑定、平台任务层等留给第二期。

主要静默失败点(第一期必须消灭):

1. 区间写法 `192.168.10.2-192.168.10.10` → 当作单个主机名拼 URL,解析失败后仅报一条连接错误;
2. 通配符 `192.168.10.*` → `Targets()`(`ipnet.go:30`)遇 `*` 静默产出空结果;
3. 超大网段 `10.0.0.0/8` → 无上限直接展开,内存与扫描时长爆炸;
4. 裸 IPv6、逗号/空格分隔、CIDR 带端口等 → 全部当普通字符串处理。

## 三、第一期改造范围

### 3.1 统一目标解析器(核心,新增包 `common/targets`)

新建 `common/targets` 包,`common/runner` 与 `common/agent` 共用,替换各自为政的解析逻辑:

```
common/targets/
  parser.go    // Parse 主入口
  expand.go    // 范围 / CIDR / 通配符展开
  errors.go    // 结构化错误(行号 + 原因 + 建议写法)
  parser_test.go
```

接口设计:

```go
type Kind int
const (
    KindURL Kind = iota  // http(s)://...,原样透传
    KindHost              // 域名
    KindHostPort          // 域名:端口
    KindIPv4              // 裸 IPv4(展开后同属此类)
    KindIPv4Port          // IPv4:端口
)

type Target struct {
    Kind Kind
    Raw  string // 原始输入行
    Value string // 归一化后的目标(URL/域名/IP 或 host:port)
}

type LineError struct {
    Line    int    // 1-based 行号
    Input   string // 原始行
    Reason  string // 不支持原因
    Suggest string // 建议写法(对齐《格式清单》不支持表)
}

type Result struct {
    Targets   []Target    // 展开去重后,保留首次出现顺序
    RawCount  int         // 非空原始表达式数
    Issues    []LineError // 逐行错误
}

func Parse(lines []string) (*Result, error) // 存在任一错误行时 error 非 nil,Result 仍带明细
```

语法实现要点(逐条对齐《格式清单》):

- **预处理**:忽略空行,去掉每行首尾空白;不识别注释/序号/引号,含这些内容的行按解析失败报错;
- **范围**:`起始IPv4-结束IPv4`,两端完整四段、英文连字符、两侧无空格,起始 ≤ 结束,展开含两端;支持跨网段连续展开;起止相同合法(结果 1 个 IP);
- **通配符**:仅最后 1~2 段、整段 `*`、连续位于末尾;`192.168.*.10` 这类中间通配段报错;URL/查询参数中的 `*` 不按通配符展开(先按 URL 语法识别);
- **CIDR**:`net.ParseCIDR` 校验,归一到网络起点(`192.168.10.2/24` ≡ `192.168.10.0/24`);展开含网络地址与广播地址,不自动缩减 `/24` 为 254;IPv6 CIDR 报错;
- **去重**:展开后按字符串稳定去重(单 IP 与范围重叠时只保留一次,保留首次出现顺序);
- **容量上限**:非空原始表达式 ≤ 65,536;展开去重后唯一目标 ≤ 65,536;单个网段/范围展开超过 65,536 直接拒绝并指明来源行(`10.*.*.*`、`10.0.0.0/8` 落在这条);
- **明确不支持 → 结构化报错**(文案直接取自《格式清单》不支持表):缩写范围 `x.x.x.2-10`、范围内含空格、波浪号连接、逆序范围、范围/网段/通配符携带端口、端口范围表达式、中间通配段、域名通配 `*.example.com`、空格或逗号分隔多目标、URL 内嵌范围、裸 IPv6 / IPv6 网段 / IPv6 范围。

现有 `common/runner/ipnet.go` 的 `IPAddressesIPnet`(uint32 展开仅适用 IPv4)作为范围/CIDR 展开的底层实现保留,通配符展开复用同一套 uint32 位运算;`Targets()` 函数及其"遇 `*`/空格返回空"的旧语义废弃,调用方迁移到新解析器。

### 3.2 端口发现模式(新增 `common/portscan`,双模式)

```
common/portscan/
  mode.go   // 模式定义与端口清单
```

**已决策(2026-09-21)**:第一期实现 `full_tcp` 与 `fixed_ai` 双模式;**默认 `full_tcp`**(与 v1.0.0 行为一致,存量用户无感),`fixed_ai` 作为用户主动勾选的加速选项,入口放在现有"扫描配置"弹窗内(交互原型 `prototype/port-mode-prototype.html` 已评审通过)。

- `full_tcp`(默认):`1-65535`,共 65,535 个端口;
- `fixed_ai`(可选):`11434,1337,7000-9000,18789`,共 2,004 个端口,面向大范围目标的快速路径;
- 作用对象:仅 `Kind == KindIPv4` 的目标,**包括由范围 / CIDR / 通配符展开出来的 IPv4**;
- URL、域名及带端口目标走 Web 扫描路径,不做端口发现(与现行 IsIP 判断行为一致);
- 校验:仅接受 `full_tcp` / `fixed_ai`,不认识的值显式报错(延续消灭静默失败原则);空值 → `full_tcp`;
- 不提供自定义端口范围与 UDP(规格明确当前不支持)。

`internal/options.Options` 增加 `PortMode string`(默认 `full_tcp`);`common/agent/tasks.go` 的 `agentScanPorts` 常量(`tasks.go:295`)改为按模式取值,`utils.NmapScan(host, ports)` 签名已支持传入端口串,无需改动。扫描进度日志已输出 nmap 参数(`-T4 -p ...`),所用模式天然可追溯,报告再标注一次。

> 行为变更提示:现行 CIDR/范围类目标展开后**不触发**端口发现(只探 80/443),改造后展开出的 IPv4 将按所选模式做端口发现,默认 `full_tcp` 时扫描时长显著上升。缓解:解析结果输出"将做端口发现的主机数",超过阈值(建议 256)时在任务启动前告警,并提示可切换 `fixed_ai` 模式或改用 `IP:端口` 明细清单;详见第七节。

> 实施核对（2026-09-29）：上文“存量用户无感”仅适用于原本已做全量端口发现的入口。CLI 和旧 WebSocket 入口过去在模式为空时只探测 80/443；本期按统一默认值改为 `full_tcp`，对裸 IPv4 会执行 1–65535 端口发现，属于明确的兼容性变化。任务提交前的规模告警仍是后续步骤，本次未完成。

## 六、验收清单

验收 = 《格式清单》两组表格逐条走查,另加容量与模式边界:

1. **支持表 18 条**:每条格式输入后能展开/解析为文档标注的目标数量(如 `192.168.10.250-192.168.11.5` → 12 个 IP);
2. **不支持表 17 条**:每条输入产生明确报错,文案含原因与建议写法,不再出现静默失败;
3. **容量**:`192.168.0.0/16` 通过;追加任一不重叠目标被拒;`10.0.0.0/8` 被拒;
4. **端口模式**:裸 IPv4(含范围/CIDR/通配符展开)在默认 `full_tcp` 下 nmap 参数为 `1-65535`,切换 `fixed_ai` 后为 `11434,1337,7000-9000,18789`;`IP:端口` 与 URL 目标在两种模式下都不触发 nmap;非法 `port_mode` 值显式报错;Web 配置弹窗与 CLI `--port-mode` 均可切换;
5. **去重**:单 IP 与包含它的范围同时输入,唯一目标数只计一次,进度总数一致;
6. **CLI**:`-t "192.168.10.2-192.168.10.10"`、`-f targets.txt`、`--port-mode` 生效。

## 七、风险与决策点

| 风险/决策 | 对策 |
| --- | --- |
| **端口模式:已决策(2026-09-21)**——第一期实现双模式,默认 `full_tcp`(存量用户无感),`fixed_ai` 为配置弹窗内可选加速项;交互原型已评审(`prototype/port-mode-prototype.html`) | 引擎侧按模式取端口清单;默认值只需保证 `Options.PortMode = full_tcp`;大范围目标由用户主动切 `fixed_ai` 提速 |
