# 扫描端口模式前端交互设计

日期：2026-09-28

## 目标与范围

在现有 AI 基础设施扫描输入区的齿轮入口实现已确认的 B 版“扫描配置”弹窗。用户可在全量 TCP 和固定 AI 端口之间切换，并继续编辑 HTTP Headers。固定 AI 模式必须展示完整规则 `11434、1337、7000–9000、18789`，同时显示总数 2004。仅修改前端；后端已有 `port_mode` 接收能力。

本次不实现目标解析预检、逐行解析错误的新协议、扫描数量预估、CLI 默认值调整、持久化配置或自定义端口。它们属于一期计划的后续工作。

## 已确认的界面

选择 B 版单列紧凑单选行。弹窗标题为“扫描配置”，顺序为端口模式、HTTP Headers、取消与确认。全量 TCP 行显示 `1–65535`、65,535 个端口和“默认”；固定 AI 行显示 2004 个端口及全部四段规则。说明文字明确端口发现只作用于裸 IPv4 及范围、CIDR、通配符展开后的 IPv4。窄屏时弹窗保持可滚动、按钮可操作。

两种模式使用语义化单选控件，支持键盘选择和可见焦点。关闭按钮有可访问名称。页面原有的 MCP 扫描仍使用 HTTP Header 编辑，不显示端口模式。

## 组件和数据流

- `ChatArea.tsx` 持有已确认的 `httpHeaders` 与 `portMode`，后者初始为 `full_tcp`；居中和底部输入区共享这份状态。
- `FloatingInputArea.tsx` 持有弹窗开关，向弹窗传入当前配置。齿轮在存在已确认且键非空的 Header 行，或 AI 基础设施扫描选择了非默认模式时显示蓝点；MCP 扫描只按 Header 判断。
- `HttpHeaderDialog.tsx` 在 AI 基础设施扫描中呈现 B 版扫描配置，在 MCP 扫描中保留 Header 编辑。弹窗打开时复制已确认配置到本地草稿。切换模式或编辑 Header 只改变草稿；确认一次性回传两项配置并关闭，取消或关闭直接丢弃草稿。
- `ChatArea.tsx` 创建任务请求时，仅在 `taskType === 'AI-Infra-Scan'` 的 `params` 中始终写入 `port_mode`，值为 `full_tcp` 或 `fixed_ai`。其他任务的请求不含此字段。原有 Header 的请求处理保持现状。
- 移除 `ChatArea.tsx` 中未被打开的重复 Header 弹窗，避免将来出现两个状态源。

端口模式的 TypeScript 联合类型与默认值放在一个小型前端模块中；固定 AI 端口规则也集中定义，避免界面多处复制。中英文显示文案放在现有 i18n JSON 中。

## 行为边界与错误处理

UI 只能产生两个合法模式，默认值始终明确。配置弹窗不提交任务；任务仍由现有发送流程创建。如果任务创建或执行失败，继续使用现有错误展示。HTTP Header 空键沿用现有过滤逻辑。取消操作必须使蓝点、下一次打开的选中模式和最终请求都保持原值。

## 验收

1. AI 基础设施扫描默认选中全量 TCP，发送请求包含 `params.port_mode: "full_tcp"`。
2. 选择固定 AI 并确认后，弹窗显示完整规则，齿轮显示蓝点，发送请求包含 `params.port_mode: "fixed_ai"`。
3. 选择模式或修改 Header 后取消，重新打开仍显示此前已确认的配置；未提交的改动不影响请求。
4. MCP 扫描只显示 Header 编辑，其他任务不携带 `port_mode`。
5. 居中与底部输入区配置一致；中英文文案完整；窄屏和键盘操作可用。

验证方式：TypeScript 检查、前端构建，以及在浏览器中检查上述交互与请求体。当前仓库未配置前端测试脚本，不为这一界面改动额外引入测试框架。
