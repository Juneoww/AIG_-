# AI 基础设施扫描错误反馈与端口默认值设计

日期：2026-09-29

## 目标与边界

延续已完成的 B 版端口模式前端配置，完成下一段可验证闭环：AI 基础设施扫描的解析错误从 Agent 经过现有任务事件/SSE 到达页面，以逐行明细显示；CLI 与旧 WebSocket 扫描入口在未指定 `port_mode` 时按一期计划统一为 `full_tcp`。用户已明确选择这项默认值行为变更。

本次采用“Agent 结构化错误事件”方案。**不**增加创建任务前预检接口，不重写异步提交和输入框清空时序，不增加自定义端口或 UDP，不改变解析器的“任一行错误则整次扫描失败”语义，不自动扫描公网目标。未指定模式的 CLI/旧 WebSocket 将从旧行为（只走 80/443 Web 探测）转为对裸 IPv4 执行 `1-65535` 端口发现；必须在文档与验收中明确标为行为变更。

## 现有流程与改动点

前端 `ChatArea.tsx` 已在 AI 基础设施任务 `params` 中显式提交 `port_mode`。Web 服务分发任务时原样透传 `params`，Agent 的 `scanPortsAndPrepareTargets` 调用 `common/targets.Parse`。`Parse` 返回 `Result.Issues`，但 Agent 当前仅把逐行问题写日志，随后返回汇总错误。`Agent.SendError` 发出的 `ErrorEvent` 只有 `message`；任务管理器会将其原样持久化并经 SSE 推送，页面错误卡片只显示 `message`。

本次不修改 SSE 事件外层和任务存储机制，仅在 `ErrorEvent` 增加可选的 `targetIssues` 数组。每项为：

```json
{
  "line": 2,
  "input": "192.168.10.2-10",
  "reason": "不支持缩写的 IPv4 地址范围",
  "suggest": "请写完整的起止 IPv4 地址"
}
```

`line` 沿用解析器定义：1 起始；0 表示容量超限等全局问题。`input`、`suggest` 可为空。保留既有 `message` 汇总文字，使旧前端、普通错误事件继续工作。字段为可选，非解析错误不带 `targetIssues`。

## Agent 错误链路

`common/targets.Parse` 必须把分类失败行的原始输入写入 `LineError.Input`，使事件中的 `input` 不会意外为空；全局错误仍按解析器定义处理。`scanPortsAndPrepareTargets` 在 `targets.Parse` 失败时返回带 `Issues` 的专用包装错误，并保持现有汇总错误文本和失败即中止扫描的行为。Agent 统一任务执行出口使用 `errors.As` 识别此包装错误，发送 `message + targetIssues`；其他错误仍走原 `SendError(message)` 路径。可选字段只在序列化边界定义，避免把解析器的 Go 结构体直接暴露为外部 JSON 契约。错误列表按原始输入行序保持顺序，不在前端重新排序或推断原因。

## 前端呈现

`Message` 增加可选 `targetIssues` 类型。`ChatArea` 接收 SSE `error` 时仍按现有 `message/error` 逻辑取得通用摘要，并防御性读取结构化明细：仅接受数组；逐项保留 `line` 为非负整数、`reason` 为非空字符串，且可选 `input/suggest` 为字符串的项目，丢弃无效项目；没有有效项目则按普通错误展示。现有红色错误卡片保持视觉层级，在摘要下方显示逐行列表：行号（0 时显示“整体输入”）、原输入、原因、可选建议。文字由 React 正常转义，不使用原始 HTML；长 URL 自动换行，小屏可滚动。

按任务和摘要去重时，纯 `message` 事件若先到，后来同摘要事件带有效 `targetIssues`，必须更新已有卡片而非丢弃明细或生成重复卡片。反向顺序或重复投递也只保留一张包含明细的卡片。处理顺序上的队列去重不能提前吞掉详细事件；持久化任务事件重新加载后也要保留最丰富的明细。为此允许在应用状态中增加更新错误明细的窄范围 action。无 `targetIssues` 时，所有其他任务与旧错误事件的展示保持现状。中英文 UI 标签使用现有 i18n 资源；解析器 `reason/suggest` 当前为服务端中文原文，本次不发明翻译或错误码映射，英文界面仍显示这些原文，后续国际化单独处理。

SSE 的业务 `event: error` 属于任务终态，不能让失败任务继续接收无限心跳。前端收到后立即标记任务失败，保留最多 5 秒接收可能晚到的同摘要逐行明细，随后关闭连接；正常结果提前关闭。临时网络断线交给 EventSource 自动重连，不可恢复的关闭状态才清理连接。若断线时漏收终态事件，任务状态轮询也要触发同样有限的关闭窗口。离开页面时关闭实际连接并取消待执行的建连计时器；延迟建连前复查任务最新状态。任务重载时仍从持久化事件合并完整明细。

## 端口默认值

- CLI `scan`：未指定或显式传空 `--port-mode` 归一为 `full_tcp`；`fixed_ai` 保持可选，非法值显式失败。
- 旧 WebSocket `ScanRequest`：未指定或空 `port_mode` 归一为 `full_tcp`；非法值保留显式错误路径。
- REST 任务/Agent：已有空值归一为 `full_tcp`，不改变。
- `runner.Options.PortMode == ""` 的**内部**语义仍可用于跳过第二次端口发现。Agent 已在准备目标时执行 nmap，再将结果交给 Runner；不可把 `Runner.New` 的所有空值无条件改为 `full_tcp`，否则会重复扫描。
- 端口发现只作用于裸 IPv4 及范围、CIDR、通配符展开出的 IPv4；URL、域名、`IP:端口` 不做端口发现。

## 验收与验证

1. 两个及以上无效输入行：任务失败，SSE 错误仍带汇总 `message`，同时按输入顺序带每行 `line/input/reason/suggest`；页面逐行显示。全局容量错误以 `line: 0` 显示。
2. 普通失败事件没有 `targetIssues`，原有错误卡片不变。旧事件只有 `message` 时仍能展示；同摘要的纯文本与结构化错误无论到达顺序如何（包括队列处理与任务重载），最终只有一张带明细卡片。
3. CLI/旧 WebSocket 未传模式时归一为 `full_tcp`，`fixed_ai` 精确使用 `11434,1337,7000-9000,18789`；非法模式报错。Agent 内部 Runner 不重复进行端口发现。
4. 自动测试先行：解析错误包装与事件 JSON 序列化、模式默认和边界各有可重复测试；前端结构化数据的防御性解析有单测，组件在浏览器中以模拟错误事件做可视化验收。
5. 使用本机已缓存的 Go 1.23.2 Docker 镜像运行 Go 测试；运行前端类型检查与构建。仅当服务环境可用时，用回环地址或明确授权的测试目标做真实链路冒烟，不把未做的真实扫描称为通过。
6. 修改任务事件或 API 语义时核对并更新 `api.md`、`api_zh.md`、`docs/swagger.yaml` 的相关说明。未有安全 Git 基线，不自动提交或推送。
