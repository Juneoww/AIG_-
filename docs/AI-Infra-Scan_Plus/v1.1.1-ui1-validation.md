## 隔离 Docker 事务

专用 Docker-in-Docker 引擎通过真实 Bash 入口执行预检、升级和回退。外层容器 `network=none`，只读挂载工具与兼容规则交付，不挂载宿主 Docker socket，仅用无扫描能力的 seed 服务。测试副本替换镜像身份以供演练；生产源码固定真实源 ID，额外实测其拒绝 fixture 包。最终证据 `upgrade-validation/ui1-docker-fixture-02/report.json` 全部通过：

- 已安装 v1.1.1、三份实际 Compose，且不需要 v1.1.0 目录。
- `--check` 不创建目录/锁，不导入镜像、不修改现场清单。
- 损坏包、规则挂载缺失、忙碌任务和规则互斥锁均在停服前拒绝。
- 实际 stop 成功但响应异常后恢复原 Web；实际候选启动后注入失败，可恢复原 Web；诊断写盘失败不阻止恢复。
- 正常升级只改变 Web 镜像和规则管理转换器；Agent ID/启动身份、Checker 卷、端口、环境、挂载、网络和业务数据保持。
- Web 业务备份及 Checker 只读备份摘要匹配；002/004 兼容工具均能发现 UI 补丁现场。
- 回退实际启动旧 Web 后注入失败，可恢复补丁 Web、同步新 ID 收据并再次成功回退。
- 主动回退保留补丁后新增的 session、上传、MCP data、日志、`.env`、规则及版本记录。
- 开放入口后注入失败，保留已验收补丁和刚接受的写入；该失败收据可再次回退且保留全部写入。

首轮演练的 Compose null 拒绝日志保留为 RED 证据；修复后第二轮完整通过。最终随机测试容器及其匿名卷已清理，历史证据保留。
