## 扫描卡住与效率问题

| 原问题 | v1.1.1 修复 | 修复后的行为 |
| --- | --- | --- |
| 基础检测已结束，某一张截图一直不返回，整体等待后处理，页面长期显示“执行深度扫描” | 将浏览器启动、连接、页面操作、截图和清理接入真实 context，超时或取消后终止并回收浏览器进程 | 单条截图异常会明确记录，已有基础检测结果保留，报告可以生成并标注覆盖未完成 |
| 上传图片、AI 调用和部分 HTTP 请求缺少任务取消或操作截止 | 为目标 HTTP、远程指纹/漏洞初始化、附件下载、上传及 AI 后处理传递任务 context，设置可配置的操作时限 | 用户终止或操作超时能结束对应工作，不再无限等待；失败阶段进入报告 |
| 多 IP 逐个串行执行端口发现，大网段长时间停留在某个 IP 的进度上 | 默认使用 4 个受控并发进程，稳定去重，回传已处理/总目标数及逐目标错误 | 一个目标失败不会抹去其他目标的发现结果；并发数可配置，默认全 TCP 端口范围不变 |
| nmap 子进程未接入任务取消 | 引入带 context 的 nmap 调用，取消后终止并等待进程退出；支持显式配置端口发现超时 | 未完成会作为错误记录，不被解释为“没有开放端口” |
| 原镜像 nmap 文件能力包含 NET_ADMIN，但原 Compose 未授予该能力，可能出现 exec EPERM | 发布镜像仅恢复扫描所需的 NET_RAW 文件能力 | 非 root Agent 在原容器能力配置下可以执行 nmap，已完成真实回环取消验证 |

## Agent 断联、事件积压和任务状态问题

| 原问题 | v1.1.1 修复 | 修复后的行为 |
| --- | --- | --- |
| 每条进度事件都加载完整任务历史，历史越多处理越慢 | 事件状态检查只查询必要状态列，保留详情接口原有历史加载功能 | 减少大量事件下重复读取历史的开销 |
| WebSocket 读循环同步处理数据库和前端推送，慢消费阻塞心跳读取，可能误判 Agent 断联 | 持续读取控制帧，业务事件交给独立的顺序消费者；使用 256 帧/16 MiB 有界队列 | 处理慢事件时仍能读取心跳；队列溢出明确失败，已接受的事件按顺序保留，不能伪报成功 |
| Agent 实际断联后，Web 的运行任务仍长期保持 doing | 按连接归属，将仍由该连接负责的运行任务原子更新为错误并保存失联事件 | 已回传历史保留，页面明确显示失败；重连不自动重新派发或续扫 |
| 同 AgentID 重连时，旧连接清理可能删除新连接或错误结束重新分配的任务 | 增加连接身份和逐任务归属隔离，统一串行写 socket | 旧连接退出不影响新连接及其任务 |
| Agent 发送队列满或连接断开后，任务回调可能一直阻塞 | 队列等待响应任务/Agent 取消；拥塞达到截止后明确关闭连接并取消任务 | 任务可以退出，回传不完整不会被当作正常成功 |
| 前端 SSE 客户端读取过慢，写入或 Flush 阻塞事件处理；旧订阅退出可能删除新订阅 | SSE 写入串行并设置真实写截止，按连接身份清理订阅 | 默认 5 秒截止，慢客户端不能无限阻塞；重新订阅受到保护 |
| 用户先终止任务，Agent 随后回传的部分报告被终态过滤丢弃 | 接收所属连接的终止后结果，保存检测证据和覆盖缺口，但保持 terminated 状态 | 保留部分报告，不把已终止任务改成成功完成 |
| 下发任务失败删除已有历史，或报告入库失败仍标记 done | 下发失败保存明确错误及历史；报告先成功入库才能更新完成状态 | 避免历史丢失和未保存报告的假成功 |
| Web 启动时静默改写历史任务状态 | 移除启动时统一重置任务状态的调用 | 历史状态不因重启被批量改写；升级前须明确终止旧卡住任务 |

## 报告完整性问题

- 报告新增 `completion_status`、`coverage` 和 `target_errors`，记录成功、失败、未完成、端口发现失败和后处理失败情况。
- 每条结果可记录截图、上传和 AI 的后处理状态。截图或 AI 失败不会删除已经得到的基础检测证据。
- 旧界面可见的进度说明和日志同步显示“覆盖未完成”，避免只增加后台字段而继续显示全量完成。
- `score_valid=false` 时，评分不能代表全量覆盖；`score_scope=completed_targets_only` 表示仅依据已完成检测。全部目标失败时评分为 0，不再产生有效满分报告。
- 已验证“155 条结果中一条截图超时”“155 成功、21 失败”“全部失败”和“用户取消”等情况。

## 内网升级和回滚保护

- 提供配套离线包和一键脚本，支持只读 `--check`、升级和基于本次备份的回滚。
- 备份并校验数据库、上传文件、日志、配置、其他 data 及 API Checker 卷；新版使用独立目录和独立 Checker 卷，保留旧版。
- 平台包及镜像层均不携带三个基础设施规则目录，继续使用共享规则库；缺失外部规则挂载时拒绝启动扫描服务。
- 固定旧运行时及新镜像身份，校验完整包清单、路径和摘要，拒绝损坏包、忙碌任务、挂载异常及空间不足。
- 候选启动失败时恢复旧服务；诊断记录写满磁盘不能阻断恢复。
- 开放维护入口前持久化阶段记录；入口恢复部分失败时保留当前已验收服务和已接收写入，避免切回旧快照丢数据。
- 新版已有业务写入时，先保留候选数据并拒绝覆盖式回滚。
- 提供已验证历史规则交付 002/004 的 v1.1.1 管理工具适配，保持原交付和内层规则字节不变。

## 验证与边界

已通过新增定向回归、Linux race、启用 sandbox 的真实 Chromium 截图/取消、非 root nmap 取消、实际双容器正常/挂起资源扫描、25 项平台工具测试及精确冻结源码的隔离 Docker 升级/回滚故障演练。详细依据和既有全量测试限制见 [验证记录](v1.1.1-verification.md)。

本版不提供持久化断点续扫，不自动恢复已经丢失的 Agent 内存结果，也不自动处理旧版卡住任务。升级前须在旧平台终止这些任务、结束 API Checker 检查并停止人工规则编辑。旧 Checker 无活动任务计数接口，自动预检不能独立证明其空闲。

## 发布说明摘要

修复截图后处理无限等待，取消贯穿浏览器、上传、AI、HTTP、端口发现和远程规则初始化。基础检测结果保留，覆盖缺口及逐目标错误写入报告；全部失败不再显示有效的满分报告。用户终止仍保留已完成检测证据，断联已有事件保留并明确失败，不自动续扫。

修复 Web 每事件加载完整历史的性能退化，事件消费与心跳读取分离，限制队列内存；连接替换及任务归属隔离，SSE 慢客户端写入有截止，防止阻塞事件持久化。

端口发现默认4个并发进程，稳定去重、完整TCP端口范围不变。/16 全端口意味着约42.9亿个端口组合，仍需充足时间；本版不以跳过目标换取速度。

配置（Agent 容器环境，Go duration 格式）：AIG_HTTP_TIMEOUT=30s；AIG_SCREENSHOT_TIMEOUT=120s；AIG_UPLOAD_TIMEOUT=120s；AIG_AI_TIMEOUT=300s；AIG_BROWSER_CLEANUP_TIMEOUT=5s；AIG_SERVICE_HTTP_TIMEOUT=120s；AIG_NMAP_WORKERS=4（1-32）；AIG_NMAP_TIMEOUT=0（默认不截断端口发现，可显式设30m，超时会记录未完成）。Web AIG_SSE_WRITE_TIMEOUT=5s。超时不代表无漏洞，也不会删除基础结果；score_valid=false 时不能用评分代表全量覆盖。

交付仅含程序和管理工具，运行镜像每层均无 fingerprints/vuln/vuln_en 规则资源。使用同一共享规则目录，继承历史业务数据和独立复制的 API Checker 卷。

验证与已知限制见 OPERATIONS.md 及源码 docs/AI-Infra-Scan_Plus。本次不包含持久化断点续扫；旧卡死任务须先通过旧页面终止再升级。
