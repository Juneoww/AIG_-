# v1.1.1-ui1 Web 页面修复补丁

适用：已经成功升级到纯平台 v1.1.1 的 Linux amd64 旧双服务现场，运行目录 `/opt/aig/v1.1.1`、项目 `aig-v111`、容器 `ai-infra-guard-webserver-v111` 和 `ai-infra-guard-agent-v111`。补丁会交叉校验已交付镜像 ID、实际容器、三份 Compose、业务与规则挂载；未知部署在停服前拒绝。

本补丁恢复一期的“全量 TCP 端口 / 固定 AI 端口”选择，并保留 v1.1.1 的扫描停滞修复。它更新 Web 镜像，沿用现有运行目录、端口、环境、规则及历史数据，Agent 容器和 Checker 卷保持原身份。数据库无迁移。

## 接收和预检

服务器以 root 创建接收目录：

```bash
mkdir -p /opt/aig/packages/platform/v1.1.1-ui1
```

上传同一交付中的两个文件，保持原名、放在同一目录，无需解压：

- `deploy-web-ui-v1.1.1-ui1.sh`
- `AIG-web-ui-v1.1.1-ui1-linux-amd64.tar.gz`

服务器须已有 Python 3.8+、本机 Docker、Compose v2、GNU cp、iptables/ip6tables 及可用 DOCKER-USER 链。脚本不联网安装依赖或拉取镜像。

```bash
cd /opt/aig/packages/platform/v1.1.1-ui1
bash deploy-web-ui-v1.1.1-ui1.sh --check
```

预检只读，不停服务、不导入镜像、不创建升级锁或运行目录。脚本固定资源包摘要，拒绝损坏、混配、未知布局、配置漂移和待执行/执行中的扫描任务。

## 执行

维护前在页面终止或等待全部扫描任务结束，结束 API Checker 检查，并停止人工编辑规则与配置。自动空闲检查覆盖平台扫描会话；旧 Checker 无活动计数接口，其空闲须由操作者确认。

确认预检通过后：

```bash
bash deploy-web-ui-v1.1.1-ui1.sh
```

脚本在维护入口内停止并备份 Web 相关配置和业务数据，只修改 Web 镜像配置并重建 Web；记录原镜像、实际容器及恢复路径。Agent 保持运行，Checker 卷为只读复制及摘要核对，须事先结束检查，不能视作已停止 Checker 进程的冷备份。现场三份 Compose、历史数据库、上传和共享规则分别核验，沿用原来的访问地址和端口。保留脚本打印的真实备份路径。

本补丁使用独立入口；原 `deploy-platform-v1.1.1.sh` 仅支持 v1.1.0→v1.1.1，不能用于修复已安装的 v1.1.1。

## 验收

```bash
cd /opt/aig/v1.1.1
docker compose -p aig-v111 \
  -f docker-compose.intranet.yml \
  -f docker-compose.upgrade.yml \
  -f docker-compose.rules.yml ps
```

Web 镜像应为 `ai-infra-guard-webserver:v1.1.1-ui1`，Agent 仍为原 v1.1.1。脚本验收实际入口及 JS 中的两个端口选项、Web 健康、真实 Agent 连接和知识库。浏览器重新加载后，在基础设施扫描配置中应看到：

- 全量 TCP：`1–65535`，默认模式 `full_tcp`。
- 固定 AI：`11434,1337,7000-9000,18789`，模式 `fixed_ai`。

模式仅作用于裸 IPv4、CIDR/范围/通配符展开后的 IP。URL 或带端口目标继续按显式目标检测。完整性验收和真实交互回归在发布方受控环境执行；脚本不默认扫描真实业务目标。

## 回滚与异常

主动回滚使用本次脚本打印的真实备份目录：

```bash
bash /opt/aig/packages/platform/v1.1.1-ui1/deploy-web-ui-v1.1.1-ui1.sh \
  --rollback --backup /opt/aig/backups/替换为本次实际备份目录
```

补丁回滚恢复原 Web 镜像和关联配置，保留当前业务数据，不将数据库或上传回灌到升级前快照。Agent、Checker 卷及共享规则保持当前状态。

整体平台回退限制：UI 补丁及 UI 回退会同名重建 Web，原 v1.1.1 平台备份 STATE.json 的 new_web.Id 仍指向初次安装的容器；即使先回退 UI，原 deploy-platform-v1.1.1.sh --rollback 也会因身份校验拒绝。不得手改历史 STATE 或绕过校验。本补丁仅支持 Web UI 镜像回退；跨回 v1.1.0 需要单独适配回滚工具并评估新增业务数据。

补丁失败时保留阶段记录、备份及候选镜像；先核对脚本输出，不删除目录重试。若开放访问已开始，恢复逻辑保留已验收版本及其后续写入，不自动切换业务快照。断电/SIGKILL 后按记录的实际配置、镜像、阶段和维护恢复命令核对，不能保证自动恢复。

## 后续独立规则更新

补丁附带更新后的 `prepare_rules_v111.py`，仍只接受可信原始配套交付 `rules-2026.10.10-002` / `rules-2026.10.19-004`。它生成支持 `v1.1.1-ui1` Web 镜像的规则管理入口，内层规则字节保持不变。

此前已经为 v1.1.1 生成的旧兼容管理包可能只认可原 Web 标签；后续需要更新规则时，使用补丁安装后的转换器，从原始受信交付重新生成一套配套文件。转换不会执行规则更新，当前共享规则继续沿用。
